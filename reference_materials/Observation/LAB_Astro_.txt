## Helpful derived numbers (you’ll probably need these if the form asks for plate scale, FOV or aperture area)

All arithmetic shown so you can verify:

* **Plate scale (arcsec/pixel)**
  plate scale = 206.265 × (pixel size in µm) / (focal length in mm)
  \= 206.265 × 9 / 3910 = **0.4749 arcsec/pixel** (≈ **0.475″/pix**)

* **Field of view (FOV)**
  width = 1536 × 0.4749 = **729.6″ = 12.16′**
  height = 1024 × 0.4749 = **486.0″ = 8.10′**
  → **FOV ≈ 12.15′ × 8.10′**

* **Pixel area on sky**
  \= (0.4749″)^2 = **0.2256 arcsec² / pixel**

* **Aperture radius you gave**: `4 pixels`
  → aperture radius on sky = 4 × 0.4749 = **1.8996″ ≈ 1.90″**
  → aperture area (pixels) = π × 4² = **50.265 pixels**

* **Primary & secondary collecting areas** (for completeness)
  primary area = π × (0.355/2)² = **0.09890 m²**
  secondary area = π × (0.100/2)² = **0.00785 m²**
  net collecting area = primary − secondary = **0.09105 m²**
  equivalent unobstructed diameter = sqrt(4×area/π) ≈ **0.341 m = 341 mm**

## Notes

1. **Central obstruction:**
   If the calculator asks for a percent obstruction or secondary diameter, enter `100 mm` or the percent area (≈ `7.94%` area-blocking). If it only accepts an effective aperture, you can enter `341 mm` as the effective diameter — but I recommend using the real physical numbers (355 mm + 100 mm) if possible.

2. **Throughput / efficiency:**
   You originally said “Efficiency: \~100%” — that’s unrealistic (optics + filter + detector always lose photons). I suggested `0.90` per optics and `0.90` for the filter, and QE=0.70; those combine to \~57% total. If the form has separate boxes for optics, filter, QE, enter the separate values; if there’s a single “system efficiency” box enter **0.57**.

3. **Sky mag:**
   You gave **18.5 mag/arcsec²** — that’s reasonable for a bright-city-ish sky and is the value to use for Lisbon/urban sky in the R/V bands. If you test later with a darker or brighter sky, rerun the calc.

4. **Seeing vs aperture radius:**
   Your seeing is large relative to the plate scale (3.5″ FWHM ≈ 7.4 pixels). With aperture radius = 4 pixels you are using an aperture radius ≈1.9″ which is smaller than the FWHM; that will **miss flux**. **Recommendation:** set aperture radius ≈ 1.5–2 × FWHM (in pixels). For your seeing of **3.5″**, FWHM in pixels = 3.5 / 0.475 ≈ **7.37 px** → aperture radius ≈ **11–15 px**. If the form requires an aperture radius in pixels, reconsider and enter `~12 px` (not 4 px).

   * If the site is computing S/N for a point source, use the aperture radius appropriate for your seeing (I strongly recommend re-entering aperture radius ≈ `12 pixels`).
   * If you insist on 4 px because you plan to *use a small aperture and apply aperture correction*, note that the calculator will show lower S/N (because much of the flux is outside the aperture).

5. **Extended target vs point source:**
   M27 is an **extended source**. Many SN/SNR calculators assume a point source; MiRaM’s SN tool can often handle extended or surface-brightness inputs — if it lets you input surface brightness per arcsec² (mag/arcsec²), use that. For M27 you may want to enter the **surface brightness** you expect (e.g., central region surface brightness — if you don’t have this, run the calculator for a point-like central star and separately for the sky-limited surface brightness).

6. **Filter choice:**
   For nebula imaging you might run separate simulations for B, V and R because sky brightness and line contributions differ. R will have higher nebular contribution (Hα + \[N II]) and often a brighter sky.
